Notes about playwright 
----------------------

We are going with the official document tutorials from here https://playwright.dev/docs/intro


Pre-request Setup:
Node.js: latest 22.x, 24.x or 26.x.
Windows 11+, Windows Server 2019+ or Windows Subsystem for Linux (WSL).
macOS 14 (Sonoma) or later.
Debian 12 / 13, Ubuntu 22.04 / 24.04 / 26.04 (x86-64 or arm64).

How we can create the project:
Go the directory where you wanted to create your project
Create a folder with your project name.
Use below command to create playwright with typescript:

npm init playwright@latest

This will ask for few details. Give those.
Then a simple playwright project will be created with basic samples

Most of configuration details are available on playwright.config.ts

---

Below command is to run the test

npx playwright test

By default this will run on headless mode and run all tests and all project/browser configured in playwright.config.ts


---

Headed mode:

--headed    //this is to run in headed mode. So that we can see the execution in browser UI
Eg:
npx playwright test --headed

---

Project or running in one browser:
Eg:
npx playwright test --project=chromium     

//This will run the specific project or browser.
//We can find the project configuration in playwright.config.ts file

Running one file:
npx playwright test <fileWithPath>
Eg:
npx playwright test tests/example.spec.ts

//This way we can run one specific test file. Tests available in that file will run

To run from playwright trace view:
Eg:

Below is the example script and the details


import { test, expect } from '@playwright/test';

test('has title', async ({ page }) => {
  await page.goto('https://playwright.dev/');

  // Expect a title "to contain" a substring.
  await expect(page).toHaveTitle(/Playwright/);
});

test('get started link', async ({ page }) => {
  await page.goto('https://playwright.dev/');

  // Click the get started link.
  await page.getByRole('link', { name: 'Get started' }).click();

  // Expects page to have a heading with the name of Installation.
  await expect(page.getByRole('heading', { name: 'Installation' })).toBeVisible();
});

To run specific test in a test file use test name or line number:

Using line number:

npx playwright test <fileWithPath>:<lineNumber>
Eg:
npx playwright test tests/example.spec.ts:10


Using test name:

npx playwright test <fileWithPath> -g "GiveTestNameHere"
Eg:
npx playwright test tests/example.spec.ts -g "get started link"

Workers:
Workers is the number of parallel threads.
Based on cores in CPU we can also give how many workers we need to run parallelly.
So based on that value, test will run on given workers.
If there are 6 test, and if we give 2 workers. it will 3 on one worker and other 3 on another worker.

Below is the command to specific workers: 
npx playwright test <fileWithPath> --workers:<NumberOfWorker>
Eg:
npx playwright test tests/example.spec.ts --workers:2
//Here we have given 2 workers. So parallelly it will use 2 workers and run tests


npx playwright test <fileWithPath> -j <NumberOfWorker>
Eg:
npx playwright test tests/example.spec.ts -j 2
//Same here. Here we have given 2 workers. So parallelly it will use 2 workers and run tests


Below is the command to specific % of CPU. Based on % given, this will use that many worker: 
npx playwright test <fileWithPath> --workers:<GiveCPUPercentage>%
Eg:
npx playwright test tests/example.spec.ts --workers:25%
//Here we have given to use 25% of the CPU. So based on number of cores, this will allocate that many cores.

Assertion:
------

await expect(page).toHaveTitle(/Playwright/);

Here are the most popular async assertions. For the complete list, see assertions guide:



Assertion	 - Description
--
expect(locator).toBeChecked()	- Checkbox is checked
expect(locator).toBeEnabled()	- Control is enabled
expect(locator).toBeVisible()	- Element is visible
expect(locator).toContainText()	- Element contains text
expect(locator).toHaveAttribute()	- Element has attribute
expect(locator).toHaveCount()	- List of elements has given length
expect(locator).toHaveText()	- Element matches text
expect(locator).toHaveValue()	- Input element has value
expect(page).toHaveTitle()	- Page has title
expect(page).toHaveURL()	- Page has URL


Playwright also includes generic matchers like below
toEqual
toContain
toBeTruthy 

These can be used to assert any conditions. These assertions do not use the await keyword as they perform immediate synchronous checks on already available values.

Eg:
expect(success).toBeTruthy();

Tests are Isolated:
--
Playwright test is based on concept of test fixture such as the inbuild fixture.
Each test(each page variable is isolated) are isolated between tests due to browser context. This is equivalent to brand new browser.
Every test get a fresh environment, even when multiple tests are in single BrowserContext

Eg with explaination:

import { test } from '@playwright/test';

test('example test', async ({ page }) => {
  // "page" belongs to an isolated BrowserContext, created for this specific test.
});

test('another test', async ({ page }) => {
  // "page" in this second test is completely isolated from the first test.
});

Test Hooks:
--
Below are some of the test hooks which can help in different cases

test.describe()    - to declare group of tests
test.beforeEach()  - This will run before each test
test.afterEach()   - This will run after each test
test.beforeAll()   - This will run before all test
test.afterAll()    - This will run After all test

Example:
import { test, expect } from '@playwright/test';

test.describe('navigation', () => {
  test.beforeEach(async ({ page }) => {
    // Go to the starting url before each test.
    await page.goto('https://playwright.dev/');
  });

  test('main navigation', async ({ page }) => {
    // Assertions use the expect API.
    await expect(page).toHaveURL('https://playwright.dev/');
  });
});

Record the test (codegen)
--
playwright has codegen command to record and auto write the script

Use below command for record and auto write the script
npx playwright codegen <giveUrlToLaunch>
Eg:
npx playwright codegen https://demo.automationtesting.in

This command will open the browser with playwright record related options and also playwright inspector for script section
in browser, we can do the action which we need to performance and the script will be auto written in playwright inspector.
We can also use assert visibility, assert text and asert value option in the record related menus for adding assertion.
Once recording done, you can click stop.
Then we can to the playwright inspector, there we can see the script. From there we can copy and use in the required automation.


--------------------


Generating locators during recording (codegen)
--

You can use the same command which we use for record and auto write the script
Eg:
npx playwright codegen <giveUrlToLaunch>
Eg:
npx playwright codegen https://demo.automationtesting.in

This will open the browser with playwright record related options and the playwright inspectors
Then click on stop recording button on browser.
Go the place where we want to take the locator of the element
Then click on "Pick Locator" option, then go the element which you want the locator. This will show the locator during hover itself
Click the element for which you need the locator.
Now we can see the locator in the playwright inpector on below in locator tab.
We can click on copy option to copy that locator.
